🛠 排障手册

按「先看日志 → 再查端口/权限 → 最后查授权」的顺序排查，绝大多数问题都能定位。

第 0 步：确认服务真的起来了

curl -s http://127.0.0.1:9999/api/health

返回正常即服务在跑。任何平台都可以用这条命令自查。

第 1 步：看启动日志里的验签公钥指纹

这一行是判断二进制是否正确的关键

启动日志应出现 授权验签公钥指纹：278D-4852-7191-E7CE。 对不上说明二进制不是当前版本产物 —— 旧版本曾内置错误的验签公钥，会导致所有授权码校验失败。

# Linux
journalctl -u strix --no-pager | grep -i 指纹

# Windows
Get-Content C:\Strix\logs\server.log | Select-String 指纹

# macOS
grep -i 指纹 /usr/local/strix/logs/server.log

云主机最常踩的坑：-public-url 配成了回环/内网/CGNAT 地址

生成的采集端安装命令会写死这个地址

云主机（网卡只有内网 IP）如果没显式设 -public-url 或反代地址，监控端会自动反推到内网/CGNAT 地址。 此时控制台「添加主机」生成的安装命令里平台地址就是这个内网地址，目标主机执行后必然「无法连接平台」。

  1. 启动日志若打印类似 public-url 配置为回环/内网/CGNAT 地址，采集端可能无法连接 的警告，说明确实踩坑了（1.1.1 起新增该启动告警）；
  2. 给监控端显式设置对外地址：-public-url http://<你的公网IP或域名>:9999（或写入 STRIX_PUBLIC_URL / Docker .env）；
  3. 重启监控端，回到控制台「添加主机」重新生成安装命令，确认命令里的地址已变成对外地址。

授权与机器码问题

现象原因与处理
授权显示社区版、页面提示「等待签发」本机没有有效授权。去「系统 → 授权购买」看本机机器码，把机器码交给授权方签发；签发后在「导入授权码」粘贴即可
授权码导入失败确认二进制是当前版本（指纹 278D-4852-7191-E7CE）；确认授权码是给本机机器码签发的；粘贴时不要漏字符
Docker 容器重建后授权掉了机器码随容器变化。起一次容器 → 复制机器码 → 填到 .env 的 STRIX_LICENSE_MACHINE= → 重建
启动日志报「授权系统同步失败 401」这是授权中心侧的 hub-token 问题，不影响控制台功能与本地授权，可忽略或修正授权中心配置
内网完全离线、不想连授权中心启动参数加 -hub=（不能用 STRIX_HUB=）→ 平台不再访问授权中心 → 手工导入授权码
页面上客户端显示「已授权」，但又有「等待签发」字样以本机实际授权为准。若确认本机已有有效授权仍显示矛盾，重启一次服务刷新状态

端口与网络

现象原因与处理
本机能开页面，别的机器打不开① 主机防火墙未放行 9999；② 云服务器安全组未放行；③ 反向代理未配 STRIX_PUBLIC_URL
address already in use端口被占：ss -tlnp | grep 9999（Windows 用 netstat -ano | findstr 9999）找占用进程，或换端口
大屏 / 升级下载很慢或超时反代 proxy_read_timeout 调大（如 300s），client_max_body_size 调大（如 200m）

数据库与权限

现象原因与处理
日志报「打开数据库失败」STRIX_DB 指向的目录不存在或无写权限；确认目录存在且属主正确
permission denied 启动失败（Linux）chown -R strix:strix /opt/strix
SELinux avc: deniedsemanage fcontext -a -t bin_t '/opt/strix(/.*)?' && restorecon -R /opt/strix 后重启
想备份数据拷数据目录即可：Linux /opt/strix/data/、Windows C:\Strix\data\、macOS /usr/local/strix/data/、Docker ./data/。SQLite 开了 WAL，冷备份要连 -wal、-shm 一起拷（或先停服务）
升级到 1.2.0 后「数据不见了」更名后默认库文件名从 opsmonitor.db 改成了 strix.db。程序会自动识别同目录下的旧文件并沿用（启动日志会打印「沿用更名前的数据库文件」）。若日志没这句且库是空的，说明 STRIX_DB 指到了别的目录 —— 默认值是相对当前工作目录的 ./data/strix.db，手工在别处裸跑就会新建一个空库，请用 systemctl 启停并显式指定 STRIX_DB

架构选错（Exec format error）

现象原因与处理
cannot execute binary file: Exec format error二进制架构与 CPU 不一致（最常见：把 amd64 装到鲲鹏/飞腾/Apple 芯片上，或 32 位 ARM 系统）。用 uname -m 确认后换对应文件，见 产物与架构
Bad CPU type in executable（macOS）Intel Mac 上装了 darwin-arm64。Apple 芯片跑 amd64 有 Rosetta 2 兜底，反向不行
cannot execute binary file: Exec format error（armv7l 树莓派）32 位系统没有对应产物，请重装 64 位系统（aarch64）
Docker 容器反复重启、日志里有 exec format镜像架构与宿主机不一致，见 Docker 部署 的架构说明
不确定装的是哪个架构./strix-server-linux-amd64 -version 会打印 (linux/amd64)，括号里就是该二进制自报的平台架构

采集端相关

现象原因与处理
控制台看不到主机密钥不一致（采集端 -token vs 监控端 STRIX_TOKEN）；地址不可达；采集端未启动
主机显示「离线」默认 180 秒未上报即离线（STRIX_OFFLINE_SEC）；检查采集端进程与网络
采集端不自动升级远端登记过同版本号产物时，同号主机不触发升级 → 改内容必须改版本号
目标主机安装提示「授权系统尚未发布该平台」1.1.1 起采集端发布物已按 5 个平台（linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64）逐个补拉修复；若仍出现，确认监控端版本 ≥ 1.1.1 且能正常访问授权中心
Windows 7 / Server 2008 R2 上采集端双击后闪退、没有窗口也没有日志Go 1.21.5 起 runtime 的随机数源依赖 Windows 8 才有的 bcryptprimitives.dll，旧系统上进程在 runtime 初始化阶段直接退出（早于任何业务日志）。改用专用兼容产物 strix-agent-windows-amd64-win7.exe，并必须加启动参数 -remote-config off -update off —— 否则它会在 30 分钟内被平台下发的更新策略换成普通版，又闪退

平台自升级 / 版本号

现象原因与处理
自升级后没生效 / 又退回旧版1.1.3 起升级后会自动重启生效（systemd Restart=always / Docker restart: unless-stopped / nohup 自行拉起）。若手工替换二进制，务必先 rm -f /opt/strix/.strix-server.pending，否则启动会误判上次升级未生效而回滚到 .bak
启动时端口被占用1.1.3 起会自动重试最多 20 秒；仍失败则检查占用进程
采集端「已是最新」拉不下来 / 每 5 分钟反复重下internal/version/version.go 的版本号必须与上传授权系统时登记的版本号完全一致
平台「可升级到 X」但版本号永远不变，服务还反复重启授权端把旧产物登记成了新版本号（典型：改了 -v 却没重新构建，--skip-build 复用了上一版 dist/）——二进制自报版本没变，每轮同步都会「再升一次」，手动点升级还可能撞上重启窗口而报 Failed to fetch。1.1.7 起平台与采集端在替换前都会先跑新二进制的 -version 自检，自报版本不高于当前版本就直接拒绝替换；按报错重新构建、按该版本号重新上传即可（release.sh 也会在上传前比对 dist/VERSION 拦下这种误传）
控制台登录失败没反应1.1.2 起登录失败会明确提示原因（「用户名或密码错误」「账号已停用」），按提示处理即可
升级后浏览器/反代还用旧前端1.1.2 起内嵌前端统一 Cache-Control: no-cache；升级后按 Ctrl+F5 强制刷新一次
控制台看不到授权中心地址 / 没有跳转授权站的按钮1.1.4 起默认隐藏（授权站遭 DDoS 期间降低暴露面），属正常现象；机器码与同步状态照常显示。需要排障时把前端 SHOW_HUB_URL 改回 true 重新构建即可
用中文给主机命名，控制台里显示成一串 -1.1.5 起已修复（此前「一键安装」会把非 ASCII 字符清洗成 -）。换成 1.1.5 重新接入即可；已存在的这类主机可在主机列表用「重命名」改回来（管理员），历史数据会一并迁移
主机重命名后，采集端还用旧名字上报会不会又冒出一台不会。平台登记了「旧名 → 新名」映射，采集端入口（上报 / 任务 / 指令 / 配置）都会自动归位到新名字，无需重装采集端
删除了主机，过一会儿它又出现了该主机的采集端仍在运行，下次上报会被重新发现——有活着的采集端就是在线主机。要彻底不再出现，先在目标主机上 sudo systemctl disable --now strix-agent（Windows 用「卸载采集端」）

命令下发（指令通道）注意

Windows 上的管道符会被拆开

Windows 走 cmd /C 执行，裸 | 会被当管道拆开，需转义为 ^|， 或整段包进 PowerShell。内层双引号会被吞。部分系统策略还会拒绝 wmic / fsutil。

其他进程/自启问题

平台现象处理
LinuxCentOS 7 systemd 报 Unknown lvalue LimitNOFILE老 systemd 语法差异，删掉该行即可（非必需）
Windows计划任务「已就绪」但无进程看 C:\Strix\logs\server.log，常见端口占用或目录无权限
macOS提示「Apple 无法检查是否含恶意软件」sudo xattr -dr com.apple.quarantine /usr/local/strix/strix-server

还找不到原因？
