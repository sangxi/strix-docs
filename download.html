🧱 产物与架构：先选对文件

一个版本共 11 个产物：2 个角色 × 5 个平台组合，外加 1 个 Windows 旧系统兼容版。 选错架构不会「降级运行」，而是直接报 Exec format error / Bad CPU type，所以先花一分钟确认。

命名规则

strix-<角色>-<系统>-<架构>[.exe]

角色：server = 监控端（控制台 + API + 服务端探针）
      agent  = 采集端（装在被监控主机上）
系统：linux / darwin（macOS）/ windows
架构：amd64（x86_64）/ arm64（aarch64）

监控端和采集端是两个不同的程序

同一台机器可以既跑监控端又跑采集端，但两个文件都要。只装 server 不会产生任何被监控主机的指标， 只装 agent 则没有控制台可看。首次部署最少需要：一台机器跑 server + 每台被监控机跑 agent。

怎么确认自己的架构

🐧

Linux

uname -m
# x86_64        -> amd64
# aarch64/arm64 -> arm64
🍎

macOS

uname -m
# x86_64 -> amd64
# arm64  -> arm64
🖥

Windows

$env:PROCESSOR_ARCHITECTURE
# AMD64 -> amd64

Debian / Ubuntu 系还可以用 dpkg --print-architecture，它直接输出 amd64 或 arm64， 和产物命名完全一致，不容易看错。macOS 也可以用 sysctl -n machdep.cpu.brand_string 看是不是 Apple 芯片。

五个最常见的选错场景

  1. 32 位系统。本项目只提供 64 位产物。树莓派装的是 32 位 Raspberry Pi OS（armv7l）时会报 Exec format error，请换 64 位系统（aarch64），而不是找 arm 版本 —— 没有这个版本。
  2. Windows 只有 amd64。没有 arm64 与 386 产物。Windows on ARM 需要走 x64 模拟层运行， 生产环境不建议。
  3. Win7 / Server 2008 R2 用了普通版。会闪退且不留日志。必须用 -win7.exe 兼容版， 并且启动参数要带 -remote-config off -update off，否则平台下发的自动升级会在 30 分钟内把它换回普通版，接着闪退。
  4. Intel Mac 装了 arm64。Apple Silicon 机器跑 amd64 有 Rosetta 2 兜底（能跑），反过来 Intel 机器跑 arm64 完全跑不起来，会提示 Bad CPU type in executable。
  5. 看发行版选文件。Linux 产物是纯静态链接的，不看发行版、不看 glibc 版本 —— Debian、CentOS 7、 Rocky、openEuler、麒麟、统信、Alpine（musl）都用同一个文件。只有架构这一个维度。

拿到文件后先做两件事

# 1) 校验完整性（同一目录下需要有 SHA256SUMS.txt）
sha256sum -c SHA256SUMS.txt

# 2) 确认版本与架构自报正确（不启动服务，只打印信息）
chmod +x strix-server-linux-amd64
./strix-server-linux-amd64 -version
# strix-server 1.2.2 (linux/amd64) 构建于 2026-10-18T11:34:27
-version 自报的架构要和文件名一致

不一致说明文件被改名错了（有人把 arm64 的文件改成 amd64 名字），装上去只会得到一个 Exec format error。发布包里的 SHA256SUMS.txt 与 RELEASE-MANIFEST.md 会列出全部产物，可以对着核。
