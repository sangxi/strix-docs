部署方式选型

四种部署方式功能完全一致，区别只在「怎么装、怎么自启、怎么放行端口」。 与它们正交的另一个维度是平台与 CPU 架构（amd64 / arm64），选错架构文件会直接跑不起来，见 产物与架构。

三句话决策

  • 只是想尽快看到界面选 Docker —— 两条命令就起来。
  • 正式部署到 Linux 服务器选 Linux 脚本 —— 它会自动识别发行版、架构、init 系统与防火墙。
  • 单机 Windows / macOS选对应目录 —— 脚本同样一键完成安装与自启。

只提供 64 位

没有 386 / armv7 产物。32 位系统（如 32 位 Raspberry Pi OS）会报 Exec format error， 需要换成 64 位系统。完整说明与自查命令见 产物与架构。

Linux 不用担心 glibc 版本

所有 Linux 产物都是纯静态链接（无 PT_INTERP、无 DYNAMIC）， Debian / Ubuntu / CentOS 7+ / RHEL / Rocky / Fedora / openEuler / 麒麟 / 统信 / Alpine 都能直接跑， 不需要按发行版准备不同的文件。

部署前先确认三件事

  1. 主机能访问互联网吗？ 纯内网离线环境请在启动参数里加 -hub=， 完全断开授权中心，手工导入授权码即可（详见 排障手册）。
  2. 端口 9999 是否被占用 / 可放行？ 云服务器记得在安全组里放行。
  3. 二进制从哪来？ 在仓库的 release/<版本>/ 下，形如 strix-server-linux-amd64；也能从发布页按平台下载，清单见 产物与架构。
统一校验：启动日志会打印验签公钥指纹

部署完成后日志里应出现 授权验签公钥指纹：278D-4852-7191-E7CE。 不是这个值说明二进制不是当前版本（旧版内置过错误的公钥，会导致授权码全部校验失败）。
