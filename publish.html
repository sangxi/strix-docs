📤 发布与托管

这一页讲的是本站自己怎么上线，不是 Strix 怎么装。 站点是纯静态的（一堆 .html + assets/），没有构建步骤， 所以两条路都能走：Cloudflare Pages 和 GitHub Pages。两条路可以同时开，互不影响。

先记住一件事

本站所有链接、脚本、图片全部使用相对路径（assets/style.css、linux.html）， 没有一处以 / 开头的绝对路径。所以放在任何子目录下（比如 https://user.github.io/strix-docs/）都能正常工作，不用改任何文件。

发布前：先本地看一眼

别把没验证过的页面直接推上线。站点目录里任意起一个静态服务即可，不要用 file:// 双击打开 —— 那样 fetch 和部分相对路径行为会不一样。

cd D:\c\opsmonitor-web

# Python 3
python -m http.server 18080 --bind 127.0.0.1

# 或 Node
npx --yes serve -l 18080 .

# 然后浏览器打开
# http://127.0.0.1:18080/index.html
Windows 上端口被占

报 WinError 10013 不是权限问题就是端口被 Hyper-V / 保留端口段占了， 换个端口（18080、18888）即可，别去改防火墙。

路线一：Cloudflare Pages

1. 准备 Node 环境

wrangler 是 Cloudflare 官方 CLI，走 npx 调用就不必全局安装：

node -v        # 需要 18 以上
npx --yes wrangler@latest --version

2. 授权（只做一次）

两种方式，二选一：

方式命令适用
浏览器登录 npx wrangler@latest login 本机手工发布。会弹出浏览器让你点授权，凭据落在 ~/.wrangler/config/
API Token set CLOUDFLARE_API_TOKEN=... 脚本 / CI / 无浏览器环境。Token 在 Cloudflare 面板 My Profile → API Tokens 建，权限给 Cloudflare Pages:Edit
Token 方式通常还要 Account ID

账号下有多个 Cloudflare 账户时必须显式指定，否则会报「More than one account available」：

set CLOUDFLARE_ACCOUNT_ID=你的账户ID
rem ID 就在面板地址栏 dashboard.cloudflare.com/<这一段就是>/...

3. 发布

别把站点目录直接丢给 wrangler

wrangler 上传的是整个目录，包括隐藏文件。站点目录一旦 git init 过， .git/、.wrangler/、.github/ 都会被发布到公网 —— 别人可以 直接下载 https://<站点>/.wrangler/cache/wrangler-account.json 看到你的 Cloudflare 账户 ID，甚至打包走整个 git 历史。正确做法是先导出一份只含页面的干净目录：

# 1) 先确认工作区干净，发布的内容才和 git 对得上
cd D:\c\opsmonitor-web
git status --short

# 2) 导出干净目录（.gitattributes 里的 export-ignore 会顺带剔除 .github/.gitignore）
rm -rf /tmp/site && mkdir -p /tmp/site
git archive --format=tar HEAD | tar -x -C /tmp/site

# 3) 只发这个暂存目录
npx --yes wrangler@latest pages deploy /tmp/site --project-name opsmonitor-docs --commit-dirty=true

仓库里的 .gitattributes 就干这件事，别删：

.github       export-ignore
.gitignore    export-ignore
.gitattributes export-ignore

输出里会打印本次的 Deployment ID 和一个预览域名（形如 https://<hash>.opsmonitor-docs.pages.dev），正式地址始终是 https://opsmonitor-docs.pages.dev。

必须显式加 --branch production ★最容易踩的坑★

站点目录一旦变成 git 仓库，wrangler 的默认分支不再是 production，而是读当前 git 分支名。于是同一条命令会被发到 Preview 环境：命令成功、给了个 <hash>.opsmonitor-docs.pages.dev 预览地址，但 opsmonitor-docs.pages.dev 一直是旧内容 —— 看起来像「发布没生效」，其实是发错环境了。

npx --yes wrangler@latest pages deploy /tmp/site \
  --project-name opsmonitor-docs \
  --branch production --commit-dirty=true

判据：pages deployment list 里 Environment 一栏，写着 Preview 就是发错了， 写着 Production 才是正式站。

本机有现成脚本

D:\c\publish-web-cf.bat 把上面几步包好了，双击即可：它先查工作区是否干净、 再 git archive 导出到 %TEMP%\strix-docs-stage， 最后带 --branch production 发那个暂存目录。 目录、项目名都写死在脚本头部，要换改那两行 set "SITE=" / set "PROJECT="。

发错了怎么补救

Pages 的每次部署都是一份不可变快照，重新发一次只把正式域名指向新快照， 旧快照仍然挂在 <hash>.项目名.pages.dev 上公开可访问。确认新部署干净后， 把带脏文件的那几次删掉（有别名要加 -f）：

npx wrangler@latest pages deployment list --project-name opsmonitor-docs
npx wrangler@latest pages deployment delete <Deployment ID> --project-name opsmonitor-docs -f

核对是否真的干净，别只看状态码 —— 这个站没配 404.html， 任何不存在的路径都会回落成首页并返回 200。要看 Content-Type：

curl -s -o /dev/null -w "%{content_type}\n" \
  https://opsmonitor-docs.pages.dev/.wrangler/cache/wrangler-account.json
# 返回 text/html   -> 该路径不存在（回落首页），安全
# 返回 application/json -> 真的泄露了，删部署重发
项目名不要随手改

opsmonitor-docs 是沿用下来的项目名，改了等于新建一个站点， https://opsmonitor-docs.pages.dev 这个已发出去的地址就停更了。 Strix 是本项目的新名字，但项目名和域名保持不动，只改页面里的文案。

4. 回滚 / 看历史

# 列出最近几次发布
npx wrangler@latest pages deployment list --project-name opsmonitor-docs

# 把某个旧版本重新设为生产（用上一步拿到的 Deployment ID）
npx wrangler@latest pages deployment create opsmonitor-docs --deployment-id <ID>

其实最省事的回滚在网页端：Cloudflare 面板 → Workers & Pages → 项目 → Deployments 列表，任意一条右侧 ⋯ → Rollback to this deployment。

路线二：GitHub Pages

1. 站点目录本身要是一个仓库

本站和 Strix 主仓库（sangxi/Strix）是两个独立仓库，不要混。 本站对应 sangxi/strix-docs，仓库里只有 html / css / js / 截图。 首次初始化（已做过一次，换机器或重建时照抄）：

cd D:\c\opsmonitor-web
git init -b main
git add .
git commit -m "docs: Strix 部署教程 1.2.3"

git remote add origin https://github.com/sangxi/strix-docs.git
git push -u origin main

2. 页面已经带了工作流

仓库里的 .github/workflows/pages.yml 就是把仓库根目录整个发上去 （artwork 取 '.'，因为 index.html 就在根上）。不用改，除非你要把它挪进子目录。

name: Deploy static site to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v4
        with:
          path: '.'
      - id: deployment
        uses: actions/deploy-pages@v4

3. 打开 Pages 开关（关键一步，不做就一直 404）

仓库 Settings → Pages → Build and deployment → Source 选 GitHub Actions。 选完之后 push 到 main 就会自动发布，Actions 标签页能看到进度。

不想用 Actions 也行

Source 选 Deploy from a branch → 分支 main → 目录 /(root)， 同样能发。区别是这种做法不需要 pages.yml，但它不会帮你做 configure-pages 那套环境检查，出问题日志也不好读。

4. 地址与子路径

仓库名访问地址说明
<用户>.github.iohttps://<用户>.github.io/根路径，一个账号只能有一个
strix-docs（本站）https://sangxi.github.io/strix-docs/有 /strix-docs/ 子路径前缀，本站相对路径已适配
别在页面里写绝对路径

子路径部署时 href="/assets/style.css" 会指向 https://<用户>.github.io/assets/style.css（少了仓库名）→ 全站样式失效。 改页面时保持 assets/...、linux.html 这种相对写法。

5. 绑定自定义域名（可选）

仓库 Settings → Pages → Custom domain 填域名，GitHub 会往仓库根写一个 CNAME 文件； 同时到 DNS 加 CNAME 记录指向 <用户>.github.io。 证书签发要等几分钟到半小时，期间强制 HTTPS 会失败，等证书好了再勾。

常见问题

现象原因处理
命令成功，正式地址还是旧内容 发到 Preview 环境了（目录是 git 仓库时默认读分支名） 加 --branch production 重发；用 pages deployment list 看 Environment 一栏
换了内容但看起来没变 CDN / 浏览器缓存 先 Ctrl+F5 强刷；再开无痕窗口验证
GitHub 上 push 完没动静 Pages 的 Source 没选 GitHub Actions Settings → Pages 改 Source；或 Actions 里手工 Run workflow（workflow_dispatch 已开）
整站没样式、图标全丢 用了绝对路径 /assets/... 改成相对路径；子路径部署必然踩这个
点某个链接跑回首页 文件名大小写不一致（Linux 区分大小写，Windows 不区分） 本站没配 404.html，错路径会回落成首页而不是报错，最容易误判成「能打开」
导航栏图标显示成方块 系统缺该 emoji 字体 换更通用的符号（本站已把 🪟 换成 🖥，就是这个原因）
wrangler 报 More than one account Token 对应的账户不唯一 设 CLOUDFLARE_ACCOUNT_ID

发布前自检清单

🔍

内容一致性

页脚版本号 = internal/version/version.go 里的版本； 产物表里的文件名和 release/<版本>/ 实际文件逐一对应。

🚫

无残留旧标识

全站搜一遍旧品牌名与旧环境变量前缀，应为 0 处。 改完记得统一存成 LF，别让编辑器写成 CRLF。

🔗

链接可达

逐页点一遍侧栏与正文内链，本地起静态服务验证，别用 file://。

📱

不横向溢出

1280 宽下 document.scrollWidth 不应超过 clientWidth； 宽表格都套在 .table-wrap 里。

# 全站自查（在站点目录执行）
grep -rn "opsmonitor" *.html assets/site.js     # 期望：无输出
grep -c "1.2.3" assets/site.js                  # 页脚版本
ls *.html | wc -l                               # 页面数量，增删页面时同步改 site.js 的 NAV
新增页面别忘了两处

① assets/site.js 的 NAV 数组里加一项，否则侧栏点不到； ② 相邻页面的 .pager 前后链接顺手改一下，不然「下一页」会跳回首页。
