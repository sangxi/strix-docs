🖥 Windows 部署

支持 64 位 Windows 10 / 11、Windows Server 2016 及以上；Windows 7 SP1 / 8 / 8.1、Server 2008 R2 / 2012 / 2012 R2 等旧系统请用旧系统兼容版采集端（见文末专章）。原生计划任务实现开机自启，无需 NSSM 等第三方工具。

架构：Windows 只有 amd64 一种

系统产物说明
Win10 / 11、Server 2016+strix-server-windows-amd64.exe
strix-agent-windows-amd64.exe		标准版，推荐
Win7 SP1 / 8 / 8.1、Server 2008 R2 / 2012 / 2012 R2监控端：无可用产物
采集端：strix-agent-windows-amd64-win7.exe		旧系统兼容版，1.2.3 起有独立发布通道，见文末
Windows on ARM无原生产物只能靠 x64 模拟层跑标准版，生产不建议
32 位 Windows无产物请换 64 位系统

确认方法：PowerShell 里执行 $env:PROCESSOR_ARCHITECTURE，返回 AMD64 即对应 -amd64 产物。

快速开始

在管理员 PowerShell 里执行（脚本会自己做提权检查，权限不足会直接拦住并提示）：

cd C:\你的目录\deploy\windows
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force   # 仅本次会话放开脚本执行
.\install.ps1

脚本会自动：

  1. 把 strix-server.exe 装到 C:\Strix\（自动从脚本上级目录找二进制）
  2. 生成 C:\Strix\start-server.cmd，把端口、密钥、账号写进去
  3. 注册开机自启计划任务 strix（SYSTEM 权限、失败自动重启 3 次）
  4. 放行防火墙端口
  5. 打印只显示一次的控制台账号与通信密钥

常用参数

.\install.ps1 -Addr :8000                          # 换端口
.\install.ps1 -Token '你的密钥' -AdminPass '你的密码'   # 指定密钥与密码
.\install.ps1 -Prefix 'D:\Strix'              # 换安装目录
.\install.ps1 -File D:\tmp\strix-server-windows-amd64.exe
.\install.ps1 -NoFirewall                          # 不动防火墙
.\install.ps1 -Uninstall                           # 卸载（保留数据）
.\uninstall.ps1 -Purge                             # 卸载并删除数据

目录规划

路径用途
C:\Strix\strix-server.exe主程序（自动更新会替换，旧版存为 .bak）
C:\Strix\start-server.cmd启动脚本（配置在这里，权限受限）
C:\Strix\data\strix.dbSQLite 数据库（备份拷这个目录）
C:\Strix\logs\server.log程序输出日志
C:\Strix\releases\采集端发布物缓存

日常运维

# 状态
Get-ScheduledTask -TaskName strix | Select-Object State
Get-Process strix-server -ErrorAction SilentlyContinue

# 看日志（跟随输出）
Get-Content C:\Strix\logs\server.log -Tail 40 -Wait

# 重启
Stop-ScheduledTask -TaskName strix; Start-ScheduledTask -TaskName strix

# 开机自启开关
Disable-ScheduledTask -TaskName strix
Enable-ScheduledTask  -TaskName strix

手工部署（不用脚本）

New-Item -ItemType Directory -Force C:\Strix\data, C:\Strix\logs
Copy-Item strix-server-windows-amd64.exe C:\Strix\strix-server.exe

# 前台试跑，确认能起来（Ctrl+C 退出）
C:\Strix\strix-server.exe -addr :9999 -db C:\Strix\data\strix.db -token 你的密钥

# 注册开机自启
$action  = New-ScheduledTaskAction -Execute 'C:\Strix\strix-server.exe' `
  -Argument '-addr :9999 -db C:\Strix\data\strix.db -token 你的密钥' `
  -WorkingDirectory 'C:\Strix'
$trigger = New-ScheduledTaskTrigger -AtStartup
$principal = New-ScheduledTaskPrincipal -UserId 'SYSTEM' -RunLevel Highest
Register-ScheduledTask -TaskName strix -Action $action -Trigger $trigger -Principal $principal -Force

# 放行防火墙
New-NetFirewallRule -DisplayName 'Strix' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 9999

常见排障

现象处理
计划任务「已就绪」但没进程看 logs\server.log；常见是端口被占或数据目录无权限
提示脚本被禁用用 Set-ExecutionPolicy -Scope Process Bypass，或 powershell -ExecutionPolicy Bypass -File .\install.ps1
本机能开、别的机器打不开防火墙规则未生效，或安全组/上层设备未放行 9999
日志乱码Get-Content -Encoding Default 读取，或记事本打开
启动日志指纹不是 278D-4852-7191-E7CE二进制不是本版本产物
采集端连不上检查 -token 是否与监控端 STRIX_TOKEN 一致，以及 9999 是否可达

旧系统兼容版（Win7 / 8.1 / Server 2008 R2 / 2012 / 2012 R2）

为什么正式版在这些系统上跑不起来：Go 1.21 起编译出来的程序最低要求 Windows 10 / Server 2016， 官方把 Win7 / 8 / 8.1、Server 2008 R2 / 2012 / 2012 R2 全部列为不再支持。具体崩法有三个：

  • 随机数源从 RtlGenRandom 换成了 ProcessPrng，后者来自 bcryptprimitives.dll —— Win7 / 2008 R2 上根本没有这个 DLL，函数指针是 NULL，一调用就 0xc0000005
  • 砍掉了 WSASocket 的旧系统回退，没有 WSASocketW 的机器直接失败
  • 砍掉了 LoadLibraryEx 的旧回退与旧版控制台句柄处理

因为它崩在 runtime 初始化阶段，早于任何一行业务日志，所以现象是 「双击后黑窗口一闪就没了，既没有报错框也没有日志」——这几乎总是这个原因，不是配置问题。

系统用哪个采集端一键安装脚本
Windows 10 / 11、Server 2016 及以上strix-agent-windows-amd64.exe可以用
Server 2012 / 2012 R2strix-agent-windows-amd64-win7.exe
（Go 1.20.14 构建，自报「旧系统兼容版」）		可以用（自带 PowerShell 4.0）
Win7 SP1 / 8 / 8.1、Server 2008 R2改用 schtasks.exe 手工注册，见下文

第 1 步：把兼容版登记到平台上

授权系统那条线按「版本 + 平台 + 架构」只存一份产物，所以兼容版不走自动上传， 要在控制台里手工登记一次（1.2.3 起支持）：

  1. 打开上传面板控制台 →「在线升级」→「采集端发布物（本地上传）」
  2. 版本号填与正式版完全一致的号系统选 Windows，架构选 amd64
  3. 文件选兼容版产物strix-agent-windows-amd64-win7.exe
  4. 勾选「旧系统兼容版」然后点上传；不勾就会当成正式版，把原来那份覆盖掉

上传后列表里会出现两行、同一个版本号，一行带「兼容版」徽标、一行带「正式版」徽标。 两份产物并存互不覆盖，各有各的「最新」标记。

第 2 步：装到旧系统上

1.2.3 起安装脚本会自己判断系统版本：读 [Environment]::OSVersion.Version， Major < 10 即认定旧系统，自动去要兼容版，并打印一行 「系统版本 6.3，属于旧版 Windows，将安装「旧系统兼容版」采集端」。直接跑就行：

cd C:\你的目录\deploy\windows
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\install.ps1

Win7 / Server 2008 R2 手工部署（这两套系统只有 PowerShell 2.0，没有 Register-ScheduledTask，用系统自带的 schtasks.exe）：

# 1) 先确认二进制能在本机跑起来 —— 应打印「旧系统兼容版」
strix-agent-windows-amd64-win7.exe -version

# 2) 前台跑一次，确认能连上平台（Ctrl+C 退出）
strix-agent-windows-amd64-win7.exe -server http://你的监控端IP:9999 -token 你的通信密钥 -name 主机名

# 3) 注册开机自启（schtasks 是 cmd 命令，PowerShell 里直接这样一行跑；
#    不要用 ^ 续行，那是 cmd 的写法，PowerShell 不认）
schtasks /Create /TN strix-agent /SC ONSTART /RU SYSTEM /RL HIGHEST /F /TR "C:\Strix\strix-agent.exe -server http://你的监控端IP:9999 -token 你的通信密钥 -name 主机名"

# 4) 启动
schtasks /Run /TN strix-agent
1.2.3 起不再需要 -remote-config off -update off

兼容版里注入了身份标记（version.LegacyWindows），查版本和自升级时都会带 &legacy=1，平台因此只回兼容版。所以「自动升级把它换回正式版、换完又闪退」 这条路从协议上被堵死了。

仍在跑 1.2.2 及更早兼容版的老机器：先升到 1.2.3 的兼容版，升级成功后就能把 -remote-config off -update off 两个参数撤掉。

监控端仍然不要装在旧系统上

上面说的兼容版只针对采集端。监控端（strix-server）只提供 Win10 / Server 2016+ 的产物， 旧系统上请改用 Linux 服务器或 Docker 部署，把采集端留在旧机器上即可。
