🐳 Docker 部署

最快的上手方式：两条命令起来，适合 1Panel / 宝塔面板环境，也适合本地试用。 镜像的 CPU 架构跟随宿主机，amd64 与 arm64 都支持。

快速开始

cd deploy/docker
cp .env.example .env
vi .env                     # 改 STRIX_ADMIN_PASS、STRIX_TOKEN、STRIX_PUBLIC_URL
docker compose up -d
docker compose logs -f

打开 http://宿主机IP:9999，用 .env 里的账号登录。 数据落在宿主机 deploy/docker/data/，采集端发布物落在 releases/。

架构：镜像跟着宿主机走

本项目只发布 amd64 / arm64 两种 Linux 产物，镜像构建时按目标架构挑文件：

宿主机镜像架构说明
x86_64 服务器 / Intel Maclinux/amd64默认路径，直接可用
鲲鹏 / 飞腾 / 倚天、Apple 芯片 Maclinux/arm64BuildKit 自动传 TARGETARCH=arm64，取 release/<版本>/strix-server-linux-arm64
32 位 ARM（armv7l）—无产物，请换 64 位系统
 
# 手里这个 docker 是什么架构？
docker version --format '{{.Server.Arch}}'        # 输出 amd64 或 arm64
docker buildx version                             # 有输出说明 BuildKit/buildx 可用，能自动选架构
老 docker（没有 BuildKit）

不会传 TARGETARCH，Dockerfile 里会退回默认值 amd64。 这类环境在 arm64 机器上要显式指定（命令在 deploy/docker 里执行，上下文是仓库根 ..）：

docker build -f Dockerfile.binary \
  --build-arg VERSION=1.2.3 --build-arg TARGETARCH=arm64 \
  -t strix/strix-server:1.2.3 ..
# 或者直接用源码构建（按构建机架构出镜像）：
docker build -f Dockerfile --build-arg VERSION=1.2.3 -t strix/strix-server:1.2.3 ..

想在 Intel 上构建一个 arm64 镜像（拿到 ARM 服务器上跑），用 buildx 交叉构建：

docker buildx build --platform linux/arm64 \
  -f deploy/docker/Dockerfile.binary --build-arg VERSION=1.2.3 \
  -t strix/strix-server:1.2.3 --load .

两种构建方式

方式Dockerfile特点
用现成二进制Dockerfile.binary不用 Go 环境、不用联网拉模块，几十秒出镜像。依赖仓库里已有 release/1.2.3/strix-server-linux-amd64（或 -arm64）
从源码构建Dockerfile适合 GitHub 用户 / CI，需要能拉取 Go 模块；产物是构建机架构的原生镜像
构建上下文必须是仓库根目录

compose 里已配好 context: ../..，因为 Dockerfile.binary 需要读取 release/<版本>/ 下的二进制。若手动构建，务必用仓库根目录作上下文。

⚠️ 最容易踩的坑：机器码会变，授权会失效

容器重建后机器码会跟着变

监控端的授权绑定机器码，而容器重建后主机名、网卡信息都会变，机器码跟着变 → 授权判定失效。

正确做法：

  1. 先起一次容器；
  2. 打开控制台「系统 → 授权购买」，复制页面显示的本机机器码（形如 C317-6E8B-BAE5-A8A6）；
  3. 把它填到 .env 的 STRIX_LICENSE_MACHINE=；
  4. docker compose up -d 重建。

之后无论容器怎么重建，机器码都是固定的，授权不会掉。

目录与数据

位置用途
./data/SQLite 数据库（挂到容器 /data，文件名 strix.db）
./releases/从授权系统代拉的采集端发布物（挂到 /releases）
容器 /opt/strix工作目录

数据都在宿主机 ./data/，docker compose down 不会丢。备份直接打包这个目录即可。

采集端如何接入

采集端要能访问到宿主机的 9999（不是容器 IP）：

# 方式一：采集端装在宿主机 / 其它机器上，直接指宿主机地址
./strix-agent-linux-amd64 -server http://10.0.0.5:9999 -token 与 STRIX_TOKEN 一致 -name web-01

# 方式二：控制台「监控 → 添加主机」复制一键安装命令，命令里自动带上平台地址
采集端发布物从哪来

平台会把授权系统上登记的采集端发布物代拉到 ./releases/ 再分发给内网主机。 首次需要容器能出网；完全离线时，手工把 strix-agent-* 放进 ./releases/， 或在控制台「在线升级」页面上传登记。

反向代理（可选，推荐生产用）

server {
    listen 80;
    server_name monitor.example.com;

    location / {
        proxy_pass http://127.0.0.1:9999;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;   # 探测任务与升级下载可能较慢
        client_max_body_size 200m; # 上传采集端发布物
    }
}
挂了域名 HTTPS 之后

记得把 .env 的 STRIX_PUBLIC_URL 改成对外地址（例如 https://monitor.example.com），否则「一键安装采集端」生成的命令会指到内网 IP。

常用命令

docker compose ps                      # 状态
docker compose logs -f --tail=100      # 日志
docker compose restart                 # 重启
docker compose down                    # 停止（保留数据）
docker compose up -d --build           # 改完 .env 后重建
docker compose exec strix-server /usr/local/bin/strix-server -version   # 容器内版本与架构
docker compose exec strix-server wget -qO- http://127.0.0.1:9999/api/health   # 容器内健康检查

常见排障

现象处理
找不到 release/1.2.3/...构建上下文不对，必须在仓库根目录执行，或 docker compose -f deploy/docker/docker-compose.yml --project-directory . build；也可能是该版本还没生成 release/1.2.3/（ls release/ 确认）
exec format error / 容器反复重启镜像架构与宿主机不一致。arm64 机器上要确保 TARGETARCH=arm64，或改用源码构建
架构对但特别慢很可能在 QEMU 模拟下跑（amd64 镜像跑在 arm64 宿主）。用上面的 -version 命令看括号里的架构是否为宿主架构
容器起来就退出docker compose logs 看日志；常见是 /data 挂载点权限或端口占用
页面能开、别的机器打不开宿主机防火墙 / 云安全组没放行 9999
授权显示社区版且「等待签发」确认 STRIX_LICENSE_MACHINE 与授权中心绑定的机器码一致；再点「立即从授权系统拉取授权」
容器内访问授权中心超时容器需出网访问默认授权中心（地址已内置在程序里，无需手动填写）；内网离线请用 -hub= 完全离线并手工导入授权码
时间差 8 小时确认 TZ=Asia/Shanghai 已传入，且宿主机时间正确
